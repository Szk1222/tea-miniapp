但好消息是：**你项目里真正值钱的东西，比那条简历更深**。它有一个 RAG 问答系统没有的难点——**事实必须来自硬规则，模型不能自由生成**。这在面试里是能展开讲 10 分钟的设计取舍。

## 四、想往 RAG 方向靠，需要补什么

如果你希望简历上能出现「向量数据库」「LangChain」，下面四件事做完再写，工作量不大但会让整条链路名副其实：

| # | 要补的 | 怎么做 | 做完能写什么 |
|---|---|---|---|
| 1 | 真接向量库 | `rag.js` 里 `denseScores()` 换成 Chroma/pgvector 查询，融合与重排逻辑不用动（注释里已标好切入位置） | 「基于 ChromaDB 的向量检索与混合召回」 |
| 2 | 真实 PDF/文档语料 | 把《中国居民膳食指南》《药食同源目录》等公开文档做成 PDF，加一个解析入 pipeline 的脚本 | 「中文 PDF 知识库，完成文档解析与分块」 |
| 3 | 检索评测做扎实 | `eval.js` 的 21 条扩到 100+ 条并支持导出报告 | 「可复现的检索效果评测集」 |
| 4 | 压测 | 用 `autocannon` 或 `wrk` 打 `/api/agent/chat.json`（不带模型），拿到 QPS / P99 | 「单机 QPS xxx，P99 xxx ms」 |

**LangChain 这条建议不写。** 用 LangChain 重写一遍唯一的收益是简历上多一个词，代价是引入 20+ 依赖、丢掉「零依赖手写流式协议解析」这个更能展示工程能力的点。面试官问「为什么用 LangChain」你答「因为简历要写」，反而扣分。

如果 JD 明确要求 LangChain，正确姿势是：**真写一遍**，然后简历写「基于 LangChain 实现工具编排与检索链，同时手写 SSE 流式协议解析以保证首字延迟」。

## 五、面试追问预案

这个项目最容易被追问的 8 个问题，答好了比简历本身加分：

**1. 「大模型会不会瞎编茶方？」**
不会。模型没有直接产出茶方的能力，只能调 `recommend_tea`，工具返回的 id 由服务端拼成卡片。模型能编的只有自然语言部分，而那部分过了出站净化。这是**架构上消除**，不是靠提示词求它别编。

**2. 「为什么不用纯 RAG，让模型基于检索结果回答？」**
试过这个思路，但养生场景的检索结果要变成「克重 + 冲泡 + 禁忌」的结构化输出，纯 RAG 会让模型复述时漏项或改数。所以推荐类走 Function Call 返回结构化块，只有科普类才走检索增强。**两类需求拆成两条链路**。

**3. 「检索为什么不用向量？」**
中文短查询（「湿气重」「怕冷」）用 TF-IDF + 二元/三元组召回已经很稳，向量在这里是加分不是必需。所以我把它做成可开关的一个通道（`EMBEDDING_ENABLED`），默认关闭省成本，要开就开。融合与重排对两种模式是同一套代码。

**4. 「中文检索踩过什么坑？」**（这题最能分层，建议准备）
三个：疑问词污染（「湿气重怎么办」被「怎么办」带到「喝了不舒服怎么办」）、单字兜底（给未登录词兜底 idf 会让「恐龙蛋化石」命中化痰类文档）、三元组缺失（只有 bigram 时「睡不好」切成「睡不/不好」，召不回任何东西）。对应三个改法：停用短语表、未登录词丢弃 + 只取长度≥2 的强词项做候选、加入 trigram。

**5. 「流式输出下怎么做内容安全？」**
这是最难的一题，也是最能体现深度的一题。模型逐 token 吐字，禁词可能跨 chunk 被切开。固定长度 holdback 只是降低概率，不能消除。我用的是「安全前缀」判定：只要存在禁词横跨切分点，就把切分点往后抬到该词结束位置，重新校验直到稳定。用 1~5 字符全部切分粒度穷举验证过零泄漏。

**6. 「模型挂了怎么办？」**
端上三级降级：本地医疗红线先拦（不发网络）→ 连续失败 2 次熔断 60 秒 → 回落本地规则引擎。产品退化成规则版本，仍然可用。这也是为什么 `agent.js` 没被删掉。

**7. 「多轮上下文怎么管的？」**
服务端按 sessionId 存会话，滑动窗口保留最近 8 轮，最近推荐的茶方 id 回传给端上并在下一轮作为 `exclude_ids` 传回，实现「换一批」不会重复推荐。会话有 TTL 回收，清空对话时端上会换一个 sessionId。

**8. 「API Key 放哪？」**
只放服务端环境变量。小程序包可反编译，端上绝不能持有 Key，所以对话必须过一层自建服务。

## 六、一句话总结

这个项目**可以作为「RAG 交互问答服务系统」这类条目来写**，但要把叙事重心从「我用了什么框架」挪到「我做了什么取舍」：

- 截图那条的卖点是**会用 LangChain + ChromaDB 搭一条 RAG 链路**；
- 你这个的卖点是**知道 RAG 在什么场景下不该用，并且用架构把模型的能力边界框死**。

后者在面试里是更难被问倒的那种。
