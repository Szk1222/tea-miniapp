## tealife 中医体质养生茶推荐小程序 · 从零搭建（首版）

**需求**：tealife 品牌，主营「茶品类型 + 根据中医体质推荐」，要求简洁移动端设计、信息层级清晰、统一图标、不使用 Emoji。用户提供了完整方案（Agent 系统提示词、MVP 框架、开发关键问题）。

**交付**：完整原生微信小程序工程（70 个文件），根目录即小程序根，`project.config.json` appid 为 `touristappid` 可用测试号直接打开。

### 工程结构
- 页面 11 个：首页 / 问茶顾问 / 茶方库 / 我的 / 体质测评 / 体质档案 / 茶方详情 / 我的茶方(收藏+浏览记录) / 养生知识库 / 知识详情 / 免责声明与隐私
- 组件 3 个：`icon`（SVG data-uri 图标）、`tea-card`（茶方卡片 row/grid 两态）、`custom-tab-bar`
- 数据层 `data/`：constitutions(9)、teas(18)、questions(10 题 + 基础信息)、knowledge(22 味食材 + 10 条常识)
- 逻辑层 `utils/`：icons / store / engine(评分·判定·匹配) / agent(对话规则 + 合规风控)

### 关键技术决策
1. **图标方案**：用 `background-image: url(data:image/svg+xml,...)` 而非 `<image src="*.svg">`，规避小程序端 SVG 兼容性差异；`utils/icons.js` 内置 58 个 24×24 线性图标。
2. **自定义 tabBar**：原生 tabBar 只吃 PNG，改用 `custom: true` 才能统一使用 SVG 图标；对话页输入框聚焦时通过 `getTabBar().setData({hidden:true})` 隐藏 tabBar 避让键盘。
3. **体质判定修正**：初版用原始分比较，导致「痰湿倾向明显」的用户被判成平和质（平和质题量满分 30，其他体质 7–18）。改为按 `raw / 该体质理论最高分` 的相对倾向度比较后判定正确。
4. **WXML 表达式限制**：WXML 不支持 `array.indexOf()` 等方法调用，多选状态改用 `condSel` / `tasteSel` 对象映射 + `{{condSel[item]}}` 取布尔值。
5. **自定义组件事件**：`onTap="handler"` 不被识别，必须写 `bind:tap="handler"`。

### 合规实现

- 特殊人群（孕期/哺乳/产后/儿童/慢性病/过敏）风险提示前置，高危直接终止推荐
- 所有推荐末尾自动附免责声明；测评前有特殊人群确认弹窗

### 这一轮修掉的 4 个真实 bug（都值得记住）
1. **正则 g 标志状态污染**：`/x/g.test()` 会推进 lastIndex，导致净化随机漏检。词表已改成纯字符串数组，彻底绕开。

4. **规则词库覆盖不足**：「我是不是得了什么病」「长期吃降压药」未被识别。已补进 MEDICAL_RULES / SPECIAL_RULES。

## 第四轮：真机调试发现的前端渲染问题修复

**用户报告**：「问茶」页左上角「AI 增强」胶囊在真机上被压扁、底色/描边/圆角异常；茶方详情页右下角「问顾问是否适合我」按钮图标与文字挤在一起、按钮偏出/被裁切。

### 根因一：把胶囊样式挂在行内 `<text>` 上（确定的 bug）
- `pages/chat/chat.wxml` 里「AI 增强 / 本地模式」写的是 `<text class="chat-top__tag chat-top__tag--mode">`，
  配 `padding: 3rpx 14rpx; border-radius: 999rpx; background` —— `<text>` 在真机是行内元素，
  **不认垂直内边距**，结果被压成一条细扁色块，圆角与描边渲染也异常
- 附带一个坑：该 `<text>` 的文本内容在 WXML 里跨了 3 行（全项目唯一一处），
  行内 `<text>` 内的换行/缩进会渲染成空白，导致胶囊内文字左右不对称
- 改法：换成 `<view>` + 固定 `height: 40rpx` + `line-height: 40rpx`（垂直居中）+ `text-align: center`（水平居中）
  + `flex: 0 0 auto` + `white-space: nowrap`，文本内容写在一行
- 同类问题用脚本扫全项目又找出 1 处：`pages/knowledge/knowledge.wxml` 的「我的体质」标签
  （`.c-item__mine`，同样挂在 `<text>` 上）已一并改成 `<view>`
- 扫描脚本思路：遍历 wxml 里 `<text class="X">`，再看 X 的规则体是否含 background/border-radius/padding/height

### 根因二：间距依赖 flex `gap` + 缺溢出兜底
- `.bottom-bar__main { flex: 1; gap: 10rpx }`：`gap` 在部分 WebView 上不生效 → 图标与文字直接贴死；
  且 `flex: 1` 没配 `min-width: 0`，内容理论上可撑出胶囊
- 改法：间距一律改 `margin-left`（设计稿 `preview/design-preview.html` 的 `.btnline` 用的是 `gap: 6px` = 12rpx，
  原来写的 `gap: 10rpx` 本身就比设计稿紧）；图标 `flex: 0 0 auto`、
  文字 `nowrap + overflow:hidden + text-overflow:ellipsis`、主按钮 `min-width:0 + overflow:hidden + padding: 0 20rpx`
- 左右三个固定项 96 → 92rpx，给主按钮多留 12rpx；胶囊阴影 20rpx → 16rpx（原来的阴影会被屏幕底边裁掉）
- 同一结构 `pages/knowledge-detail` 底部按钮一起改

### 验证
- 自写校验脚本：73 项（JSON 有效性 / WXML 标签配平 / JS 语法）全部通过
- 复查扫描：全项目已无「行内 `<text>` 承载底色+圆角+内边距」的写法

## 第五轮：真机渲染问题（第二批）

**用户报告**：① 首页「九种体质」渲染成一列，没有自适应；② 每种茶方点进详情页，会先弹「该茶方不存在」再出现详情。

### 根因二：`tea-card` 用 `tap` 作为自定义事件名 → 一次点击触发两次跳转（确定的 bug）
- `components/tea-card/tea-card.js` 里 `this.triggerEvent('tap', { id })`，
  各页面写 `<tea-card bind:tap="openTea" />`
- 真机上组件的 `bind:tap` 会**同时**收到两个事件：
  1. `triggerEvent('tap')` → `e.detail = { id }`（正确）
  2. 组件内原生 `tap` 冒泡 → `e.detail = { x, y }`（**没有 id**）
- 于是 `openTea` 被调用两次：第一次带正确 id 正常进详情；第二次拼出 `?id=undefined`，
  又压了一个详情页 → `teas.get('undefined')` 为空 → 弹「茶方不存在」→ 900ms 后 `navigateBack`
  → 用户观感就是「先弹提示，再出现详情」
- **改法（两层）**：
  1. 自定义事件改名 `tap` → `select`，9 处用法全部改 `bind:select="openTea"`
  2. 所有 `openTea` 加 `const id = e.detail && e.detail.id; if (!id) return;` 兜底
- **通用规则**：自定义组件 `triggerEvent` 的事件名**绝不要用 `tap`/`longpress` 等原生冒泡事件名**，
  否则父级 `bind:xxx` 会收到两次、detail 结构还不一样
- `tea-detail.js` 的 `onLoad` 兜底也修了：无上级页面时（分享链接被截断）不再死等 `navigateBack`，
  改为 `getCurrentPages().length > 1 ? navigateBack : switchTab('/pages/tea/tea')`

### 根因一：两列网格用了 `calc(50% - 9rpx)` + flex `gap`
- 涉及 `pages/index/index.wxss` 的 `.const-grid/.const-item`（首页九种体质）
  和 `pages/knowledge/knowledge.wxss` 的 `.i-grid/.i-item`（知识库食材网格），写法完全一致
- 三个叠加的兼容风险：
  1. `calc()` 里带 `rpx`：部分安卓 WebView 先按 CSS 解析（`rpx` 非法单位）→ **整条 `width` 声明被丢弃**
     → `width` 退化成 `auto`，卡片按内容宽度排布
  2. `flex gap` 老 WebView 不支持（与第四轮同因）
  3. 一旦 `box-sizing` 没吃到 border-box，`50% + 左右内边距` 会超过 100% → 自动换行成**单列**
- **改法（不依赖上述任何一项）**：
  ```css
  .const-grid { display:flex; flex-direction:row; flex-wrap:wrap; justify-content:space-between; }
  .const-item { box-sizing:border-box; width:48.4%; flex:0 0 auto; margin-bottom:18rpx; }
  ```
  纯百分比宽度 + `space-between` 撑间距；`box-sizing` 显式写在同一条规则里（不依赖 app.wxss 的全局规则）
- 索引错位放开：`.const-item` 内层 `gap: 18rpx` → `.const-item__body { flex:1; min-width:0; margin-left:16rpx }`
  （顺手补了 `min-width:0`，防止长文案把卡片撑破）
- 全项目 `calc(` 只剩两处 `env(safe-area-inset-bottom)` 的用法（无 rpx，安全）

### 根因实证（用本机 Chrome 复现，结论确定）
用户续报「食材科普」也是同样问题（该页 `.i-grid` 与首页 `.const-grid` 是逐字相同的写法）。
为不再靠猜，用 `data/knowledge.js` + `data/constitutions.js` 的真实数据 + 真实样式，

| 场景 | 结果 |
|---|---|
| 旧写法 + `box-sizing: border-box` 生效 | **2 列**（正常） |
| 旧写法 + `box-sizing` 未生效（content-box） | **1 列** ← 与用户描述完全一致 |
| 旧写法 + `calc()` 整条失效（width:auto） | 2 列（靠内容宽度侥幸排成两列） |

**结论：唯一的"退化成一列"路径就是 `box-sizing` 没生效。**
`width: calc(50% - 9rpx)` + `padding: 24rpx`，在 content-box 下实际占宽 = 50% + 内边距 + 描边 > 50%
→ 两个卡片永远放不进同一行。

**关键认知**：所以修法必须把 `box-sizing: border-box` **直接写进 `.const-item` / `.i-item` 自己的规则里**，
不能依赖 `app.wxss` 里那条全局的 `view, text, ... { box-sizing: border-box }`。
（`box-sizing` 是不含 rpx 的普通声明，只要样式被解析就必然生效，因此这一改是"兜到底"的。）

## 第八轮：接入 GitHub Actions（CI / 部署）

**仓库已改名**：`Szk1222/-` → **`Szk1222/tea-miniapp`**（原名 `-` 是占位符）。
`git remote set-url origin https://github.com/Szk1222/tea-miniapp.git` 已同步；仓库仍为**私有**。

### 流水线设计：一个文件、三个 job、用 `needs` 做闸门
`.github/workflows/ci-deploy.yml`：
`verify`（语法/JSON/密钥防线/npm test）→ `needs` → `image`（推 GHCR）+ `miniprogram`（传体验版）。
- **为什么不拆成多个 workflow 文件**：拆开就得上 `workflow_run` 或重复一遍校验步骤；
  放一个文件里用 `needs`，「校验不过就不发布」是**依赖图保证**的，不是靠约定
- `miniprogram` 只在 `tag v*` 或手动勾选时跑 —— 避免每次 push 都上传一堆体验版
- 顶层 `on.push.paths` 过滤掉 `.workbuddy/`、`docs/`：这些改动不该触发构建

### 两个必须记住的坑
1. **仓库名 `-` 不是合法 Docker 镜像名**：Docker 要求分隔符两侧都有字母数字，单独一个 `-` 不合法。
   所以镜像名固定 `chalifang-agent` 而非 `<owner>/<repo>`；且 GHCR 要求路径全小写，
   账号 `Szk1222` 必须 `tr '[:upper:]' '[:lower:]'` 转小写
2. **YAML 块标量里的 `#` 是字面内容，不是注释**：`tags: |` 里写注释会被当成一个标签传给
   metadata-action。注释要放在块标量外面

### `latest` 标签不要用 `{{is_default_branch}}`
它取决于仓库设置里的默认分支；若默认分支与 `master` 不一致，`latest` 会**静默地永远不产出**。
改为显式判断：`enable=${{ github.ref == 'refs/heads/master' || github.ref == 'refs/heads/main' }}`

### 小程序上传（`.github/scripts/upload-miniprogram.js`）
- 用 **API 而非 CLI 长参数**：CLI 参数随版本变动，容易出现「本地能跑、CI 报未知参数」
- **`require('miniprogram-ci')` 要排在环境校验之后**：否则依赖没装上时先抛
  MODULE_NOT_FOUND，把真正的原因盖掉（已用 4 条失败路径实测）
- 装在**全局**而非项目内：项目内的 `node_modules/` 会落进上传目录；靠 `NODE_PATH=$(npm root -g)` 解析
- 上传密钥走 `Secrets.MINIPROGRAM_PRIVATE_KEY`（密钥文件的 base64 单行文本），
  只在 runner 临时目录出现，工作流结束即销毁
- **IP 白名单是最大的坑**：GitHub 托管 runner 出口 IP 是动态的（Azure 段，每周变），
  密钥一旦开了 IP 白名单**必然上传失败**。要么关白名单，要么用自托管 runner

### CI 里的密钥防线（独立成一道）
`verify` 作业里除了 `.env 是否被追踪`，还加了 `git grep -lE 'ark-[A-Za-z0-9_-]{24,}'` 明文扫描。
**只报文件名、不回显内容** —— 否则扫描本身就把密钥打印进 CI 日志了（公开仓库可见）。

### 验证手法（在无 GitHub 环境时很有用）
- YAML 用 `pyyaml` 解析 + 结构断言（job/needs/steps 完整性、`uses` 是否固定版本）；
  注意 pyyaml 按 YAML 1.1 会把裸 `on:` 解析成布尔 `True`，要做兼容
- **shell 步骤在本地实跑一遍**：YAML 合法 ≠ 脚本能跑。把 `run:` 的脚本体原样在 Git Bash 跑，
  本次就是这样确认了三段脚本在 `set -euo pipefail` 下都正常
- PowerShell 安装路径：`C:\Users\25823\.workbuddy\binaries\python\envs\default\Scripts\pip.exe`

### 阻塞点：本机无法推送
- 本机 Git 是 WorkBuddy 自带 PortableGit，**无 `gh` CLI**，只能 `git` + `curl` 打 `api.github.com`
- `credential.helper` 指向 Git Credential Manager 2.9.0，但在无交互环境下**会一直挂起等输入**
  （`GIT_TERMINAL_PROMPT=0` + `GIT_ASKPASS=echo` 也拦不住，复现 3 次全部 `timeout` 退出 124）
- 判定「仓库是私有」的可靠手法：`git -c credential.helper= ls-remote origin`
  → 返回 `Invalid username or token` 即私有（匿名可读的公开仓库会直接列出 ref）
- 结论：**推送仍需用户提供 PAT**（与上一轮相同）

### ⚠️ PAT 权限要求（容易漏）
本次推送**新增了 `.github/workflows/` 文件**。GitHub 会拒绝缺少 `workflow` 权限的令牌：
`refusing to allow a Personal Access Token to create or update workflow`。
fine-grained PAT 需要同时勾：**Contents: Read and write** + **Workflows: Read and write**。

### Token 安全处理（沿用上一轮手法）
`-c credential.helper` 内联 shell helper + `TOKEN` 走**进程环境变量**（单引号包裹，
git 调 sh 时才展开，因此不出现在 argv）；配合 `GIT_TERMINAL_PROMPT=0`；
输出统一 `sed -e 's/github_pat_[A-Za-z0-9_]*/<TOKEN>/g'` 脱敏；
推送后核验 `grep -c github_pat .git/config` → 0，`git remote get-url origin` 无内嵌凭证。
